# API узлов Pixso

Pixso повторяет Figma Plugin API, но набор свойств зависит от сборки. Общее
правило: **любое обращение к свойству узла может бросить исключение**, а любой
вызов с набором полей может упасть целиком из-за одного незнакомого поля. Поэтому
здесь всё написано в защитной манере; это не паранойя, а то, чем отличается
плагин, который работает на стенде, от плагина, который работает на демо.

## Глобальный объект

Он называется `pixso`, но сборки понимают и `figma`. Проверяй через `typeof`,
иначе поймаешь `ReferenceError` на отсутствующем имени:

```js
var API = (function () {
  try { if (typeof pixso !== 'undefined' && pixso) { return pixso; } } catch (e) {}
  try { if (typeof figma !== 'undefined' && figma) { return figma; } } catch (e) {}
  return null;
})();
```

Дальше в коде только `API.*`. Это же делает плагин переносимым между Pixso и
Figma почти без правок.

## Защитное чтение свойств

```js
function prop(node, name) {
  try { return node[name]; } catch (e) { return undefined; }
}

function safeNum(v) { var n = Number(v); return isFinite(n) ? n : 0; }
function numOr(v, fallback) { var n = Number(v); return isFinite(n) ? n : fallback; }
function strOr(v, fallback) { return (typeof v === 'string' && v) ? v : fallback; }
```

Читай через `prop` всё, кроме `id` и `type`. Особенно это касается свойств,
появившихся в новых версиях API: `absoluteRenderBounds`, `strokeCap`,
`listOptions`, `blendMode`, `clipsContent`.

## Смешанные значения: `API.mixed`

Если у узла свойство различается по слоям или по буквам, вместо значения
приходит `API.mixed` (уникальный символ). Сравнивать надо именно с ним, иначе
плагин попытается работать с символом как со значением:

```js
if (paints === API.mixed) { /* заливка разная у слоёв, объектом не повторить */ }
if (prop(node, 'cornerRadius') === API.mixed) { /* разные радиусы у углов */ }
```

Это частый источник «почему блок ушёл картинкой»: смешанное значение нельзя
перенести одним объектом, и честнее снять картинкой, чем приблизить.

## Выделение и обход холста

```js
var selection = [];
try { selection = API.currentPage.selection || []; } catch (e) { selection = []; }

var children = [];
try { children = API.currentPage.children || []; } catch (e) { children = []; }
```

Полезные привычки:

- **Выделили слой внутри фрейма, работать надо с фреймом.** Поднимись к
  ближайшему подходящему родителю, вместо того чтобы говорить «ничего не
  выделено».
- **Порядок «как на холсте»** это сортировка по `y`, затем по `x`, а не порядок
  выделения: пользователь ожидает первого. Простая сортировка по `y` ломается на
  ряду кадров, где один сдвинут на пиксель: он вылетает из своего ряда. Если
  порядок важен (нумерация, слайды), сначала собери кадры в ряды по вертикальному
  перекрытию (порог: примерно треть меньшей высоты), а внутри ряда сортируй
  по `x`.
- **Что считать «кадром»**: обычно `FRAME`, `COMPONENT`, `COMPONENT_SET`,
  `INSTANCE`, `SECTION`. Держи это отдельной картой, а не длинным `if`.
- **`API.on('selectionchange', …)`** обновляет список сам. Оберни в `try/catch`:
  событие поддерживается не всеми сборками. И оставь кнопку «перечитать»: правки
  внутри макета без смены выделения событием не приходят.

## Геометрия относительно кадра

Координаты узла нужны относительно кадра, а не страницы. Считай через
`absoluteTransform` (он учитывает вложенность и повороты), с запасным путём на
случай, если его нет:

```js
function geometry(node, frame) {
  var w = safeNum(node.width), h = safeNum(node.height);
  if (!(w > 0) || !(h > 0)) { return null; }
  var nt = null, ft = null;
  try { nt = node.absoluteTransform; } catch (e) {}
  try { ft = frame.absoluteTransform; } catch (e) {}
  if (nt && ft && nt.length >= 2 && ft.length >= 2) {
    var cx = nt[0][2] + (w / 2) * nt[0][0] + (h / 2) * nt[0][1];
    var cy = nt[1][2] + (w / 2) * nt[1][0] + (h / 2) * nt[1][1];
    return { x: (cx - ft[0][2]) - w / 2, y: (cy - ft[1][2]) - h / 2,
             width: w, height: h, rotation: numOr(node.rotation, 0) };
  }
  /* запасной путь: складываем x/y до кадра */
  var x = 0, y = 0, cur = node, guard = 0;
  while (cur && cur !== frame && guard < 64) {
    x += safeNum(cur.x); y += safeNum(cur.y); cur = cur.parent; guard++;
  }
  return { x: x, y: y, width: w, height: h, rotation: 0 };
}
```

Счётчик `guard` не паранойя: битое дерево с циклом в `parent` встречается, и без
ограничителя плагин зависнет насмерть.

Линия это особый случай: у неё нулевая высота, и проверка `h > 0` её отбраковывает.
Считай её отдельно.

## Экспорт растра

```js
node.exportAsync({ format: 'PNG', constraint: { type: 'SCALE', value: 2 } })
node.exportAsync({ format: 'PNG', constraint: { type: 'WIDTH', value: 320 } })
node.exportAsync({ format: 'JPG', constraint: { type: 'SCALE', value: 2 } })
```

Что надо знать:

- **`SCALE`** для основного снимка, **`WIDTH`** для миниатюр. Если различаешь
  вызовы в тестах, различай именно по `constraint.type`.
- **Формат может быть не поддержан.** `JPG` есть не везде: оберни в `try/catch`
  и вернись к `PNG`, а не падай.
- **Неотсечённый фрейм отдаёт картинку больше себя.** Если `clipsContent ===
  false` и содержимое выходит за края, снимок вырастет вместе с вылетом, и
  расчёт координат поедет. Включи `clipsContent` на время съёмки и верни как
  было, обязательно в `finally`, иначе чужой макет останется испорченным.
- **Скрытие слоёв перед съёмкой.** Чтобы текст не оказался и на картинке, и
  поверх неё, слои временно скрываются. Правила: прячь **после** того, как
  описание объекта готово (иначе при сбое потеряешь и то, и другое); маску не
  трогай: поедет всё, что она обрезает; восстанавливай в `finally`; часть слоёв
  скрыть не удастся (внутри компонентов), это надо записать в журнал, а не
  проглотить.

## Текст и его куски

**`getStyledTextSegments` в Pixso заглушка.** В веб-сборке метод есть, но всегда
отдаёт пустой список, в типингах 2.0.4 он закомментирован (разобрано 13.10.2026).
Плагин, который на него опирается, молча решит, что в тексте нет ни одного куска.

Стиль куска текста дают методы диапазона: `getRangeFillStyleId(start, end)`
и `getRangeTextStyleId(start, end)` возвращают id стиля или `API.mixed`, если
стилей в диапазоне несколько. Отрезки с одним стилем находятся делением
пополам, пока у куска не окажется один стиль. Запись через
`setRangeFillStyleId` и `setRangeTextStyleId`. Остальные свойства куска
читайте теми же `getRange*`, каждый вызов в `try/catch`: набор методов зависит
от сборки. Что прочитать не удалось, запишите в журнал, пользователю важно
знать, что, например, ссылки в тексте этой сборкой не читаются.

Начертания шрифтов: флагами выражаются только Bold и Italic. SemiBold, Light,
Extended, Condensed это часть имени гарнитуры (`SB Sans Display Extended`), и
переносить их надо именем, иначе на другой машине шрифт не найдётся.

## Создание и правка узлов

Пока плагин только читает документ, испортить чужой макет он не может. Как
только начинает писать, может испортить, и вот на чём это ломается.

**Шрифт надо загрузить до того, как задавать текст.** Присваивание `characters`
без загруженного шрифта бросает исключение:

```js
API.loadFontAsync({ family: 'SB Sans Text', style: 'Regular' })
  .then(function () { node.characters = '1'; });
```

На стенде нужного шрифта может не оказаться вовсе. Перебирай список: свой,
затем шрифт, который уже используется в этом макете, затем системный
(Inter/Roboto/Arial); если не загрузился ни один, скажи об этом честной ошибкой,
а не молчи.

**В экземпляр компонента слой не добавить.** У `INSTANCE` содержимое
заблокировано: `appendChild` бросит. Кладите объект рядом с кадром и пишите
в журнал, почему он оказался снаружи.

**Кадр с автолейаутом переставит вашего ребёнка по своим правилам** и сдвинет
чужую вёрстку. Нужен абсолютный режим. Фигмовское `layoutPositioning = 'ABSOLUTE'`
Pixso принимает без ошибки, но может не применить: у свойств автолейаута в Pixso
два имени, и работает родное, здесь `autoLayoutAbsolutePos = true`. Ставьте оба
и проверяйте по фактическому положению слоя. Если не встало, кладите рядом,
а не ломайте макет. Остальные родные имена (`stackMode`, `stackSpacing`,
`stackChildCounterSizing` и другие) в `pitfalls.md`, грабля 7.

**Повторный запуск не должен плодить дубликаты.** Помечай свои узлы
(`setPluginData(key, value)`) и при следующем запуске находи и заменяй прежние.
Это надёжнее галочки «обновить, а не добавить»: пользователь про неё забудет, а
макет засорится.

**Любое временное изменение возвращай в `finally`.** Скрытая видимость,
включённый `clipsContent`, поднятый слой: всё это чужой документ. Плагин,
который упал на середине и оставил макет испорченным, второй раз не запустят.

## Хранилище настроек

`localStorage` в окне недоступен (origin `null` → `SecurityError`). Настройки
живут в `clientStorage` на стороне `main.js`:

```js
API.clientStorage.getAsync(KEY)   // Promise
API.clientStorage.setAsync(KEY, value)
```

Оба вызова могут отсутствовать или зависнуть. Оборачивай так, чтобы плагин
работал и без хранилища:

```js
function loadSettings() {
  var fallback = withDefaults(null), attempt;
  try { attempt = API.clientStorage.getAsync(KEY); } catch (e) { return Promise.resolve(fallback); }
  if (!attempt || typeof attempt.then !== 'function') { return Promise.resolve(fallback); }
  return new Promise(function (resolve) {
    var settled = false;
    var finish = function (v) { if (!settled) { settled = true; resolve(v || fallback); } };
    attempt.then(function (v) { finish(withDefaults(v)); })['catch'](function () { finish(fallback); });
    setTimeout(function () { finish(fallback); }, 1500);   /* не ждать вечно */
  });
}
```

Запись асинхронная: перед `closePlugin()` дай ей дописать
(`setTimeout(…, 400)`), иначе настройка потеряется.

## Команды меню

Пункт меню приходит в `API.command`. Читай защитно (свойства может не быть):

```js
var COMMAND = (function () {
  try { return String(API.command || ''); } catch (e) { return ''; }
})();
```

Блок `menu` при этом **не нужен**: с проверенным манифестом плагин открывается
нажатием на карточку, и `COMMAND` при обычном запуске пустой, это нормально.
Пункты меню с настройками (вроде «Качество 1×/2×/3×») плохо стареют: настройка
живёт в двух местах, и меню начинает противоречить окну. Настройки держите
в окне. Про манифест подробно в `publishing.md`.

## Уведомления и закрытие

```js
function notify(text) { try { API.notify(String(text)); } catch (e) {} }
API.closePlugin();
```

`notify` показывает всплывашку поверх холста и годится для команд, которые не
открывают окно. Закрывать плагин по своей инициативе стоит только там, где
пользователь этого ждёт: у окна есть своя кнопка закрытия.
