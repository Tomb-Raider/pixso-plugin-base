## Условия работы

- Внешними плагинами сообщества пользоваться нельзя, только своими.
- **Никакого npm и сборщиков.** Плагин это три текстовых файла: `manifest.json`,
  `main.js`, `ui.html`. Всё остальное пишем руками. В корпоративном контуре
  внешний реестр пакетов недоступен.
- Проверять плагин будем в Pixso Desktop на своей машине и на корпоративном
  стенде. Если на стенде нет терминала, собранный плагин (`release/`) должен
  лежать в репозитории готовым и пересобираться перед каждым коммитом.
- Окно верстаем по DAIS (https://daisforge.github.io/dais-ui/), токены уже
  стоят в каркасе. Подробно в `references/ui-dais.md`.

## Как устроен плагин

| Файл | Где выполняется | Что доступно |
|---|---|---|
| `main.js` | песочница | документ Pixso; нет DOM, сети, файлов |
| `ui.html` | iframe с пустым origin | весь Web API; нет доступа к документу |

Обмен сообщениями: `pixso.ui.postMessage` вниз,
`parent.postMessage({ pluginMessage }, '*')` наверх.

Манифест ровно из шести полей, набор проверен запуском на стенде 01.09.2026.
В корне плагина он ссылается на файлы рядом с собой, как в каркасе:

```json
{
  "id": "moy_plagin",
  "name": "Мой плагин",
  "main": "./main.js",
  "ui": "./ui.html",
  "permissions": ["activeDocument", "currentPage", "currentSelection"],
  "editorType": ["pixso", "dev"]
}
```

Сборка (`node tools/make-local-build.js`) кладёт рядом `release/` и `local-build/`,
где пути уже ведут на `dist/main.js` и `dist/ui.html`. Манифест **берётся из
образца и не додумывается**: ни `menu`, ни метаданных (`type`, `manifestVersion`,
`host`, `version`, `author`, `description`, `icon`) не нужно. Ошибка в манифесте
не похожа на ошибку: карточка есть, нажатие не делает ничего, в консоли ни строки.

## Грабли, каждая стоила часов отладки

1. **Опубликованный плагин молча не запускается из-за архива.** `manifest.json`
   обязан лежать в корне zip первой записью. Архив собирать только `./pack.sh`,
   никогда «Сжать» в Finder: тот кладёт папку-обёртку и мусор macOS.
2. **Файл из `manifest.ui` может прийти пустым.** Окно белое, хотя код работает.
   Обход: разметка вшивается в скрипт, это делает `tools/make-local-build.js`.
   Поле `ui` из манифеста при этом **не убирать**, файл в пакете оставить.
3. **Пути в манифесте считаются от папки самого манифеста.** Если файла по пути
   нет, плагин молча не запускается.
4. **Канал «окно → плагин» работает не во всех сборках Pixso** (в Desktop 2.2.7
   команды из окна не доходят, на стенде с 2.3.0 доходят). Генерация живёт
   в `main.js`; обработчик вешается и присваиванием `ui.onmessage`, и подпиской
   `ui.on('message')`, до `showUI` и после; стартовые данные плагин присылает сам.
5. **Одно нажатие может прийти два-пять раз** по разным каналам. Все сообщения
   между окном и песочницей нумеровать и обрабатывать только первое.
6. **`clientStorage` может не ответить никогда.** Ожидание под таймером.
   `localStorage` в окне запрещён.
7. **Фигмовские имена свойств автолейаута принимаются и молча не работают.**
   Работают родные `stack*` и `autoLayoutAbsolutePos`, ставить оба набора
   и проверять по фактическому размеру. `resize()` выключает «по содержимому».
8. **Мастеров библиотечных компонентов в дереве страниц нет**, идти от
   экземпляров через `mainComponent`. `findAll` внутрь экземпляра не заходит.
9. **`getStyledTextSegments` заглушка**, стиль куска текста через
   `getRangeFillStyleId` и `getRangeTextStyleId`.
10. **`exportAsync` не применяет прозрачность слоя**, переносить её вручную.
11. **Встроенная консоль плагинов бесполезна** для локально загруженных:
    диагностику показывать в самом окне.

## Что себя оправдало

- **Измерять, а не гадать.** Если непонятно, почему не работает, сначала добавь
  диагностику в окно плагина: какие каналы сработали, что пришло, что не встало.
  Потом чини.
- **Проверки без Pixso.** `tools/harness.js` гоняет логику окна, а
  `tools/main-harness.js` гоняет `main.js` на подставном документе. Так ошибки
  ловятся до запуска в приложении.
- **Не приблизительно, а точно.** Если что-то нельзя повторить один в один,
  лучше честная картинка и строка в журнале, чем похожий объект.
- Комментарии в коде и коммиты по-русски, объясняют «почему», а не «что».

## Порядок сборки и запуска

```bash
node tools/harness.js              # логика окна без Pixso
node tools/main-harness.js         # логика main.js без Pixso
node tools/dev-server.js           # отладка с горячей перезагрузкой, порт 5201
node tools/make-local-build.js     # local-build/ и release/
./pack.sh                          # архив для публикации publish/<id>.zip
```

В Pixso: панель плагинов, Upload a plugin, Local plugin, выбрать
`local-build/manifest.json`. Запускать нажатием на карточку.
