# База для плагинов Pixso

Опыт разработки плагинов Pixso в закрытом корпоративном контуре. Что на самом деле работает, где Pixso ломается молча и как это обойти

Репозиторий написан так, чтобы его можно было целиком отдать ИИ-агенту и сразу писать плагин

## Что внутри

| Папка или файл | Что это |
|---|---|
| [skill/pixso-plugin](skill/pixso-plugin) | скилл для агента. Инструкция, ловушки Pixso с обходами, рабочий каркас плагина с моком, проверками и сборкой архива. **Начинать с него** |
| [skill/pixso-plugin/references/pitfalls.md](skill/pixso-plugin/references/pitfalls.md) | все грабли с датами проверок. В начале таблица «Если что-то не работает»: что видно, почему и как проверить |
| [skill/pixso-plugin/references/ui-dais.md](skill/pixso-plugin/references/ui-dais.md) | окно плагина по DAIS: где смотреть компоненты, токены, контролы, иконки |
| [skill/pixso-plugin/assets/scaffold](skill/pixso-plugin/assets/scaffold) | каркас нового плагина, копируется целиком |
| [ПРОМТ-ДЛЯ-НОВОГО-ЧАТА.md](ПРОМТ-ДЛЯ-НОВОГО-ЧАТА.md) | первое сообщение агенту, если скилл поставить некуда |
| [tools/pix-reader](tools/pix-reader) | читалка файла .pix без Pixso. Дерево слоёв, ключи компонентов, родные имена свойств автолейаута |

## Как отдать агенту

**Claude Code.** Положить скилл в папку скиллов, дальше агент сам берёт его, когда речь идёт о плагине Pixso

```bash
git clone https://github.com/Tomb-Raider/pixso-plugin-base.git
mkdir -p ~/.claude/skills
cp -r pixso-plugin-base/skill/pixso-plugin ~/.claude/skills/
```

**Другой агент или чат.** Дать ему прочитать папку `skill/pixso-plugin` целиком: `SKILL.md` и `references`. Если файлы дать нельзя, вставить первым сообщением [ПРОМТ-ДЛЯ-НОВОГО-ЧАТА.md](ПРОМТ-ДЛЯ-НОВОГО-ЧАТА.md) и дописать в конце задачу плагина

**Новый плагин** начинается с копии каркаса

```bash
cp -r pixso-plugin-base/skill/pixso-plugin/assets/scaffold/. мой-плагин/
```

## Три правила, которые дались тяжелее всего

**Манифест берётся из проверенного образца и не додумывается.** Ровно шесть полей `id`, `name`, `main`, `ui`, `permissions`, `editorType`. Ошибка в наборе полей не похожа на ошибку: карточка плагина есть, нажатие ничего не делает, в консоли пусто

**Архив собирает только скрипт.** «Сжать» в Finder кладёт внутрь папку-обёртку и служебные файлы macOS, и опубликованный плагин молча не запускается. `pack.sh` из каркаса собирает архив и проверяет его так же, как его читает Pixso

**Сначала измерить, потом чинить.** Если непонятно, почему не работает, плагин должен сам показать в окне цифры и причины. На угадывании уходят дни, на диагностике один заход

## Окно плагина

Рекомендуем верстать окна по [DAIS](https://daisforge.github.io/dais-ui/), UI kit дизайн-системы FinAI на атомах [SDDS FinAI](https://plasma.sberdevices.ru/sdds-finai-storybook/). Тогда окна плагинов разных авторов выглядят одинаково, и дизайнеру не нужно переучиваться. Каркас уже в этих цветах. Если у вашей команды своя дизайн-система, подставьте её токены в переменные в начале `ui.html`

## Где проверено

Корпоративный стенд с клиентом Pixso 2.3.0 работает полностью. Pixso Desktop 2.2.7 для macOS не передаёт сообщения из окна в плагин и не отдаёт файл окна, обходы в каркасе рассчитаны и на него, но лучше обновиться

## Что нужно на компьютере

Плагин это три текстовых файла `manifest.json`, `main.js`, `ui.html`, без npm и сборщиков. Для проверок и сборки нужны Node 18 или новее, Python 3, `bash` и `zip`. Читалке .pix нужен Node 22.15 или новее. Снимки экрана из `references/testing.md` рассчитаны на macOS и Google Chrome
